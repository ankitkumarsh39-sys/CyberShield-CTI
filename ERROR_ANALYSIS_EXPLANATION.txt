WHAT HAPPENED:
  The program tried to start but couldn't find your VirusTotal API key.
  This is a CRITICAL error that prevents the entire program from running.

WHY IT HAPPENED:

     https://www.virustotal.com → Settings → API Key
  4. Save the file
  5. Run the program again

ERROR #4: SSL CERTIFICATE VERIFICATION FAILED
================================================================================

ERROR MESSAGE:
  2026-03-20 04:54:55 - ERROR - Re-analysis failed: 
  HTTPSConnectionPool(host='www.virustotal.com', port=443): 
  Max retries exceeded with url: /api/v3/domains/telegram.me 
  (Caused by SSLError(SSLCertVerificationError(1, 
  '[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: 
  self-signed certificate in certificate chain (_ssl.c:1081)')))

WHAT HAPPENED:
  When trying to connect to VirusTotal (HTTPS), the SSL certificate
  validation failed. This is a SECURITY CHECK - your computer doesn't
  trust the certificate presented by VirusTotal.

WHY IT HAPPENED:
  This can happen due to:
  
  1. CORPORATE FIREWALL/PROXY
     Your company's firewall intercepts HTTPS and replaces certificates.
     This is very common in corporate networks.
  
  2. SSL/TLS CERTIFICATE ISSUE
     The certificate chain on your system is incomplete or outdated.
  
  3. ANTIVIRUS/SECURITY SOFTWARE
     Some antivirus programs intercept HTTPS connections.
  
  4. NETWORK ISSUES
     Corrupted data or MITM (Man-in-the-Middle) attack (unlikely).

THE GOOD NEWS:
  The code ALREADY handles this! Look at this part:
    try:
        res = self.session.get(api_url, timeout=10)
    except requests.exceptions.SSLError as ssl_err:
        logging.warning(f"SSL verification failed for VT lookup...")
        res = self.session.get(api_url, timeout=10, verify=False)
  
  The program automatically retries WITHOUT SSL verification (verify=False).

HOW TO FIX IT:
  1. Check if you're behind a corporate firewall/proxy
  2. If yes, configure proxy settings in Python:
     
     In your code, add:
       import os
       os.environ['REQUESTS_CA_BUNDLE'] = 'C:\\path\\to\\corporate\\cert.pem'
     
     Or update Python's certificate store
  
  3. If still failing, the error logs show it's handled gracefully
     The program continues anyway (just with verify=False)

SECURITY NOTE:
  verify=False means the program doesn't check if the certificate is legit.
  This is okay in this case because:
  • We're just querying public APIs
  • No sensitive data is being sent
  • This is a workaround, not best practice
  
  But in production/security-critical apps, you should fix the certificate issue!

PYTHON LESSON:
  SSL/TLS = Secure connection protocol
  Certificate = Digital proof of identity (like ID card for websites)
  
  When you visit https://example.com:
    Browser says: "Hi, I need to verify you're really example.com"
    Server says: "Here's my certificate"
    Browser checks: "Is this certificate valid? Signed by trusted authority?"
    
  If check fails:
    Browser says: "I don't trust you!"
    Connection blocked!

ERROR #5: I/O OPERATION ON CLOSED FILE
================================================================================

ERROR MESSAGE:
  2026-03-20 05:43:16 - CRITICAL - FATAL ERROR in generate_report: 
  I/O operation on closed file.

WHAT HAPPENED:
  The program tried to write to a file that was already closed.
  This is like trying to write in a notebook that you already put away!

WHY IT HAPPENED:
  This happens when:
  
  Problem Scenario:
    with open(report_path, "w") as f:
        f.write("Line 1\n")
        f.write("Line 2\n")
    # File automatically closes here ^^^
    
    # Now trying to use f again:
    f.write("Line 3\n")  # ERROR! File is closed!

  In your code, this might happen if:
    1. You close a file but then try to write to it again
    2. You have multiple file handles to same file
    3. File object is passed around and closed prematurely

HOW TO FIX IT:
  Make sure all file operations are inside the "with" block:
  
  WRONG:
    with open(report_path, "w") as f:
        f.write("Line 1\n")
    # File closes here
    f.write("Line 2\n")  # ERROR!
  
  CORRECT:
    with open(report_path, "w") as f:
        f.write("Line 1\n")
        f.write("Line 2\n")  # Still inside with block, file is open
  # File closes here
  
  Or reopen the file:
    with open(report_path, "w") as f:
        f.write("Line 1\n")
    
    with open(report_path, "a") as f:  # "a" = append
        f.write("Line 2\n")

PYTHON LESSON:
  File operations:
    open()   = Open file and get file handle
    write()  = Write data (file must be open)
    close()  = Close file (file must be open first)
    with     = Context manager - auto-closes file
  
  "with" is the BEST practice:
    with open("file.txt", "w") as f:
        f.write("Hello")
    # Automatically closes f, even if error happens

ERROR #6: NETWORK TIMEOUT
================================================================================

ERROR MESSAGE:
  2026-03-20 06:06:47 - ERROR - Re-analysis failed: 
  HTTPSConnectionPool(host='www.virustotal.com', port=443): 
  Read timed out. (read timeout=5)

WHAT HAPPENED:
  The program asked VirusTotal for data but waited too long for a response.
  The server took longer than 5 seconds to respond, so the connection was
  cancelled (timeout).

WHY IT HAPPENED:
  Multiple possible reasons:
  
  1. VirusTotal Server Slow
     Their servers might be overloaded or having issues
  
  2. Network Latency
     Your internet connection is slow
  
  3. Firewall/Proxy Delay
     Corporate firewall is slow to process requests
  
  4. Your Computer Busy
     Your PC is processing too many IOCs, taking too long between requests
  
  5. ISP Issues
     Your Internet Service Provider has latency

THE GOOD NEWS:
  The code handles this! Look at the retry logic:
    if "rate limit" in msg.lower() or "429" in msg:
        wait_time = base_sleep * (2 ** retries)
        logging.warning(f"Rate limit hit...")
        time.sleep(wait_time)
        retries += 1
        continue

HOW TO FIX IT:
  1. Increase timeout (in advisory_gen.py):
     OLD:
       res = self.session.get(api_url, timeout=10)
     
     NEW:
       res = self.session.get(api_url, timeout=30)  # 30 seconds instead of 10
  
  2. Add retry logic with exponential backoff (already in code):
     First retry: wait 2 seconds
     Second retry: wait 4 seconds
     Third retry: wait 8 seconds
     etc.
  
  3. Check your internet connection
  
  4. Try during less busy times

PYTHON LESSON:
  timeout = Maximum time to wait for response (in seconds)
  
  requests.get(url, timeout=5):
    "Wait max 5 seconds for server response"
    If server doesn't respond in 5 seconds → error
    
  Exponential backoff = Gradually increase wait time
    1st attempt: immediate
    2nd attempt: wait 2s before retry
    3rd attempt: wait 4s before retry
    This prevents overwhelming a busy server!
